# 日志规范

目的：在 Mac 上跑出问题时，把一个日志文件发给我，就能定位到「哪一步、因为什么」，不用来回问。

## 怎么用

```
python3 -m wifi80211.report 抓包文件 --keys 密钥文件
```

- 每次运行默认在**当前目录**写一个 `wifi80211-年月日-时分秒.log`，固定记到 DEBUG，屏幕上只显示 WARNING 以上，并告诉你日志路径。
- `--log-level info|debug|trace`：屏幕上的级别。`trace` 会逐帧记，文件很大，只在定位某一帧时开。
- `--log-file PATH` 指定位置；`--no-log-file` 不写文件。
- `--redact`：日志里的 MAC、IPv4、域名换成稳定的短标记（同一个值得到同一个标记，看得出是同一台）。**要把日志发给别人之前加上。** 报告本身不受影响。
- 没料到的异常：退出码 70，屏幕告诉你日志路径，堆栈写在日志里。

## 级别

| 级别 | 写什么 | 例子 |
|---|---|---|
| ERROR | 做不下去 | 抓包文件读不了、没有密钥、受保护的帧一个也没解开 |
| WARNING | 结果可能不对 | 文件被截断、有帧没解开、某个握手 MIC 对不上 |
| INFO | 每个阶段的结论和数字 | 链路类型、帧数、找到几个握手、解开几个帧、几个事件 |
| DEBUG | 每个决定的理由，**按原因汇总计数** | 握手怎么配对、MIC 为什么不对、帧为什么没解开 |
| TRACE (5) | 逐帧 | 第 N 帧：类型、地址、用哪把密钥试、结果 |

## 绝对不能进日志

口令、PMK、PTK、KCK、KEK、TK、GTK、IGTK、WEP 密钥、密钥文件里的任何一行。
`logs.setup()` 装的过滤器还会把任何 16 字节（32 个十六进制字符）以上的十六进制串遮成 `<hex NB>` 兜底；随机数、MIC 要记的话只记前 4 个字节。
SSID、MAC、IP、域名可以记（定位问题需要），所以要把日志发出去之前加 `--redact`。

## 怎么写

- 每个模块 `log = logging.getLogger(__name__)`（名字自然是 `wifi80211.xxx`）。命令行入口用 `logging.getLogger("wifi80211.report")`，因为 `python -m` 运行时 `__name__` 是 `__main__`。
- 库不配置日志（包里只装了 NullHandler）；只有命令行调用 `logs.setup()`。
- 消息用 `log.info("找到 %d 个握手", n)` 的形式，不要先用 `%` 拼好再传；逐帧用 `logs.trace(log, ...)`，关闭时不会白拼字符串。
- 消息写**中文、一句话、带数字和原因**：「第 123 帧没解开：没有这对设备的握手」比「decrypt failed」有用。
- 失败要说明**原因分类**，并在阶段末尾给出分类计数（DEBUG），这样日志几行就能说清「280 个帧里 200 个没有握手、80 个 MIC 不对」。
- 不要在循环里对每帧写 INFO / DEBUG；逐帧只能是 TRACE。
- 日志不改变行为：加日志前后，所有测试的结果必须逐字相同。
